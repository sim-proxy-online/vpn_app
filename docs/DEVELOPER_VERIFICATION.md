## 2. Главное: для разработчика из России верификация, скорее всего, недоступна

Это не техническое ограничение сборки, а условие доступа к самой программе.

**Что сообщается.** Обязательная проверка личности вводится для всех разработчиков
Android-приложений под сертифицированные устройства на Android 7+. При этом
жители подсанкционных стран — России, Ирана, Кубы, КНДР — **пройти её не смогут**:
представитель Google подтвердил Ars Technica, что доступа к системе верификации у
них не будет. Устройства **внутри** этих стран при этом исключены из процедуры
проверки.

**Следствие.** Разработчик из России по-прежнему свободно распространяет приложение
внутри страны. Но за рубежом на сертифицированных устройствах его сборки будут
считаться непроверенными: установка останется возможной только через расширенный
режим — включить параметры разработчика, подтвердить, что действие не навязано
мошенником, перезагрузить устройство и подождать 24 часа.

**Сроки.** С 30 сентября 2026 г. — Бразилия, Индонезия, Сингапур, Таиланд.
В течение 2027 г. — остальной мир.

**Чего это не отменяет.** Исключения: установка через ADB и корпоративные
приложения на управляемых устройствах проверкой не затрагиваются.

**Что это значит практически.** Технического способа убрать предупреждение
«непроверенное приложение» нет — только верификация, а она для RU-разработчика
недоступна. Пользователи в России изменений не заметят; потери будут среди
аудитории за рубежом.

> Формулировки и сроки взяты из публикаций Ars Technica и CNews (август 2026).
> Актуальный для вашего аккаунта статус показывает сама консоль —
> [Android Developer Console](https://developer.android.com/developer-verification).

## 3. Что проверено и не требует действий

- APK **v2.7.0 подписан релизным ключом**, не debug-ключом.
- Отпечаток сертификата в APK **совпадает** с сертификатом в `android/release.keystore`.
- Все четыре сборки — 2.4.6, 2.4.8, 2.5.1-test, 2.7.0 — подписаны **одним ключом**.
  Обновление «поверх» установленной версии работает.
- Сертификат действует до **2053 года** (Google требует минимум до октября 2033).
- Пароли в `keystore.properties` верны — неверный пароль keystore отвергает.
- `release.keystore` и `keystore.properties` не попадают в git (строки 15–16 в `.gitignore`).

### Схемы подписи

| Схема | Есть? | Комментарий |
|---|---|---|
| v1 (JAR) | нет | не нужна: minSdk 24 = Android 7.0, где уже есть v2 |
| v2 | **да** | достаточно для установки на Android 7+ |
| v3 | нет | **рекомендуется** — только v3 даёт ротацию ключа |

Без v3 сменить ключ подписи невозможно: придётся выпускать приложение под новым
package name. Включается в `android/app/build.gradle`:

```groovy
signingConfigs {
    release {
        // ...
        enableV3Signing true
    }
}
```

Отпечаток сертификата при этом не меняется.

## 4. Бэкап ключа подписи

`android/release.keystore` — **единственная копия ключа, которым подписаны все
релизы**. Если он потеряется, обновлять приложение под тем же package name будет
невозможно: Android не установит обновление с другой подписью.

- Хранить keystore и пароли **вне репозитория и вне этой машины** — менеджер
  паролей, зашифрованный архив на отдельном носителе.
- Не убирать строки 15–16 из `.gitignore` и не коммитить ключ.
- Проверить восстановленную копию до того, как на неё полагаться:

```powershell
# должен вывести SHA-256 из раздела 1
$c = New-Object System.Security.Cryptography.X509Certificates.X509Certificate2(
  "путь\к\release.keystore", "ПАРОЛЬ")
$sha = [System.Security.Cryptography.SHA256]::Create().ComputeHash($c.RawData)
($sha | ForEach-Object { $_.ToString('X2') }) -join ''
```

## 5. Окружение сборки

| Что | Где |
|---|---|
| Keystore | `android/release.keystore` (PKCS#12, несмотря на расширение) |
| Пароли | `android/keystore.properties` (в git не хранится) |
| Alias ключа | `simproxy` |
| applicationId, versionCode | `android/app/build.gradle` |
| versionName | берётся из `package.json` автоматически |

Формат keystore — PKCS#12, хотя файл называется `.keystore`. Android Gradle Plugin
определяет формат по содержимому, поэтому сборка работает; при переносе в другие
инструменты это стоит учитывать.
